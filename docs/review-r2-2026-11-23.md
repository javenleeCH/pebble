> 评审对象：第一轮定稿 `docs/design-decisions.md`、新版 `rationale.md` / `README.md`，以及尚未同步的旧草稿、文法和样例。

## 专家与核心结论

| 专家 | 核心结论 |
|---|---|
| r2-strategy | 「可信」仍是设计目标而非能力；终止≠安全、哈希≠正确、LaTeX≠证明；需要威胁模型、保证矩阵和单后端证据链 Demo |
| r2-semantics | P0 规则仍不完备：普通比较应为 ?bool，谓词只认 true，group/distinct 需要值同一性，checked 应返回 null 并反映到类型，聚合与表达式作用域需重写 |
| r2-syntax | map→extend、on=、废 lambda 可行，但必须写死裸字段解析域；ifExpr 产生式原本就错；having/select as/全局 agg 需要明确 EBNF 与语义约束 |
| r2-compiler | DuckDB SQL 单后端可落地；HIR hash 不能证明外部引擎物理执行；MVP 删除自建 Physical Plan、Arrow/storage，改为 Schema lock + Execution Manifest + Receipt |
| r2-mvp | v0.1 仍过大；cast、时间、coalesce、split、having 等延期；唯一必保留的可信特性是确定性 HIR hash + verify 闭环 |

## 第二轮共同裁决

### 1. 收窄可信性表述

不再笼统说「被证明跑的那一份」。分层为：

- **可保证**：源码→规范化 HIR 的确定性、Schema 快照绑定、BackendArtifact（SQL）与执行请求的绑定、审批/运行工件一致性核对。
- **需信任**：编译器实现正确性、指定版本 DuckDB 的优化与执行正确性、宿主及数据快照的可信分发。
- **尚不能保证**：跨后端/跨版本结果一致、实际物理计划逐节点等于 HIR、资源硬隔离、业务逻辑正确。

LaTeX 是可读视图，hash 是完整性工具，均不是正确性证明。

### 2. 产品形态与后端

主产品是**嵌入式编译器 SDK + 受控宿主 API + 可验证证据工件**，不是代理服务或新执行引擎。M0/M1 只做 **DuckDB SQL 单后端**，不做 Polars、双后端、解释器、Cranelift/MLIR、自建 Physical Plan、Arrow 全栈或 storage crate。

链路固定为：

```text
Pebble source
  → typed canonical HIR (Logical)
  → BackendArtifact::DuckDbSql
  → specified DuckDB version executes
  → ExecutionReceipt
```

### 3. MVP 缩到「可验证最小核」

保留：MemoryTable（Table 若稳定可保留）、filter、extend、group_by+agg/全局 agg、select+as、sort+take、collect、5 个聚合函数、少量严格字符串函数、P0 语义、DuckDB codegen、canonical HIR + hash + manifest + receipt + verify。

延期：having（先用 agg 后 filter）、cast、时间函数、coalesce/nullif/ifnull、substr、split、Polars、多后端、资源硬隔离、完整沙箱、LaTeX 往返。join/distinct/write/print 若影响交付也可延至 v0.1.1。

### 4. P0 规范必须新增七组规则

1. 强 Kleene 三值逻辑真值表；
2. 谓词成立规则（filter/join/if/having 只认 true）；
3. 普通比较、判空、group/distinct 值同一性、sort 全序的分离；
4. 非空保证分析（合取取并、析取取交，可靠但不完备）；
5. 部分函数签名表（checked-null，返回类型必须可空）；
6. 聚合上下文签名表（全局/分组、空输入、全 null、溢出）；
7. 表达式作用域表（裸字段、源别名、extend/select/agg 前后可见性）。

## 后续决策者修订（2026-11-23）

决策者确认：架构允许并将支持多后端；Cranelift/MLIR 必须保留在正式计划。落地顺序调整为 DuckDB（MVP）→ Polars（M3）→ Cranelift/MLIR 原生后端（M4，含 Physical Plan/原生执行研究）。本轮对「MVP 单后端闭环」的建议保留，但不把「永不多后端/删除原生路线」作为结论。
