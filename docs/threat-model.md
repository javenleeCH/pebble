## 信任基（TCB）

| 层 | 信任什么 | 不信任什么 |
|---|---|---|
| 语言前端（parser/semantics） | 代码本身的正确性（有测试矩阵） | — |
| canonical HIR + 签名 | 内容寻址的确定性 | 编译器不被入侵的假设 |
| DuckDB（指定版本） | 执行正确性 | 物理计划不被中途篡改（外部引擎） |
| 数据文件 | build 时内容哈希已记录 | build 后不被篡改（TOCTOU 复核） |
| 宿主 | 私钥保管、max_rows 承诺 | — |

## 明确不防

- **分布式拒绝服务**（网络层的攻击面归部署平台）
- **操作系统级进程逃逸**（沙箱是 M4 原生后端的议题）
- **编译器自身被入侵后签名前的欺骗**（缓解：人审 LaTeX/SQL 后才签名，签名发生在审批侧）
- **跨版本一致性**（DuckDB 升级后行为可能变；`--pin-duckdb` 显式 pin 引擎版本）

## 与 RUN 码的映射

| 码 | 含义 | 谁产生 | 触发条件 |
|---|---|---|---|
| RUN-001 | f64 输入含非有限值 | run 预检 | 表达式求值前 |
| RUN-002 | 数据 Schema/内容校验失败 | run 前置 | TOCTOU 复核不一致 |
| RUN-003 | 终端 IO / 工件完整性失败 | run / verify | 文件不存在 / 工件哈希不匹配 / OOM 之外的引擎报错 |
| RUN-004 | 取消 / OOM / 资源配额耗尽 | run 引擎分类 | 超时被杀 / DuckDB 报 memory limit |
