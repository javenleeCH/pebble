# Pebble 设计评审记录（2026-11-23）

> 本轮由 5 位领域专家并行评审，结论作为 `docs/design-decisions.md` 定稿的依据。
> 评审对象：`rationale.md`、`docs/draft/spec/*`、`docs/draft/design/*`、`grammar/pebble.ebnf`、`examples/*`、`crates/*`。

## 专家构成

| 角色 | 视角 | 核心结论 |
|---|---|---|
| lang-designer | 语言设计 / 类型理论 | 语义层空转：null 取值留白、类型判断与指称语义脱钩、`map`≠π、官方样例 03 无法类型检查 |
| data-engineer | 数据工程 / 算子覆盖 | 表达力底座几乎为空（字符串/时间/cast/coalesce/全局聚合/having 全缺）；join 内连接+右表源算子是最深场景杀手 |
| syntax-ux | 语法 / DX | 方法链选对，但 `as`/`\|u\|`/裸字段三态混叠是最大语法债；`map`/`select` 双 π；工具链全裸（无 fmt/LSP/check） |
| compiler-arch | 编译器架构 / 性能 | Cranelift/MLIR 是战略误判；缺 Physical Plan / 存储层 / 并行模型；性能不可能当卖点 |
| ecosystem-strategist | 定位 / 生态战略 | 当前定位撑不起世界级；唯一机会是「可信数据变换」楔子；目标用户应从「业务数据开发」收窄到「低代码/数据平台安全嵌入内核」 |

## 五点共同判断（强共识）

1. **原定位「更好的批处理 DSL」无法支撑世界级**。链式语法、纯变换、非图灵完备、编译期校验都已是 PRQL/Polars/DuckDB/SQL 的桌面牌，可复制、可替代。
2. **唯一护城河是「可信」**：可证明正确、可审计、可安全嵌入。把「可数学化/LaTeX」从阶段三边角料提升为核心交付物，并配 Schema-as-code（版本化+哈希）。
3. **自研 Cranelift/MLIR 执行引擎是战略陷阱**。性能赛道是存量红海且有免费优质替代品；产品后端应优先做**代码生成器**（HIR → DuckDB SQL / Polars 表达式），自研引擎降为研究线。
4. **「可数学化」当前名不副实**：`map` 被错标为 π（应改 extend/ε）、集合 vs 多重集语义未定、`sort`/`take` 破坏「自由重排」宣称，三处裂缝须先修。
5. **表达力底座优先于新算子**：字符串/时间函数、`cast`、`coalesce`、全局聚合、`having` 是低成本高收益，应先填。

## 待 lead 裁决的分歧点

| 分歧 | 各方立场 | lead 裁决 |
|---|---|---|
| `map`/`select` 双 π | syntax-ux：合并进 `select`；data-engineer + lang-designer：保留两者、`map`→`extend` 并改 π 标 | 采纳后者：`map` 改名 `extend`，`select` 保留为真 π |
| Lambda `\|u\|` 冗余 | syntax-ux：废除，裸字段引用；其余未强推 | 方向采纳废除，标记为待样例先行验证 |
| join 右表仅源算子 | data-engineer：结构性天花板，须放开 | v0.2 放开为「任意上游流 + 命名子流绑定」 |
