# 第 3 章 诊断系统：错误码是稳定契约

> 对应文件：`crates/pebble-diagnostic/src/lib.rs`；规范：`docs/draft/spec/08-diagnostics.md`。

## 本章目标

1. 把「错误」建模成数据（码 + 严重级 + 消息 + Span + hint）；
2. 学会把「编译器怎么报错」设计成**跨版本稳定的 API**；
3. 实现一个 ~60 行的源码级渲染器。

## 诊断是数据，不是 println

错误处理的第一原则：诊断是**值**，收集起来统一渲染，绝不边走边打印：

```rust
pub struct Diagnostic {
    pub severity: Severity,   // Error / Warning / Note
    pub code: Code,            // SEM-001 这样的枚举
    pub message: String,       // 可本地化、可演进
    pub span: Option<Span>,
    pub hint: Option<String>,
}
```

携带容器同样简单：

```rust
pub struct DiagBag { pub diags: Vec<Diagnostic> }
impl DiagBag {
    pub fn has_error(&self) -> bool { ... }   // 编译闸门：任一 Error 存在则禁止 lowering
}
```

这个闸门是**整条流水线的安全阀**：parser/semantics 各自往 bag 里塞错误，`compile()` 在最后检查 `has_error()`，有错误就不产出 HIR/SQL——错误的程序不可能悄悄溜到后端。

## 错误码为什么用枚举而不是字符串

```rust
pub enum Code {
    LexIllegalChar, LexUnclosedString, LexBadEscape, LexBadNumber,
    ParUnexpected, ParOpAfterTerminal, ...
    SemUnknownField, ..., SemConstDomain, ...
    SchNoSchema, ..., SchAmbiguousBoundary,
    RunNonFiniteInput, RunSchemaValidation, RunIoFailure, RunResourceExhausted,
}
```

三个理由：

1. **穷举性**：加新码时编译器强制你更新 `as_str()` 的 match——不存在拼错字符串这种 bug；
2. **稳定契约**：规范承诺「错误码与触发条件是稳定契约，消息可演进」（08 §8.2），枚举让「改消息」与「改码」在类型上分离；
3. **测试可断言**：单测写 `expect_err(src, "SEM-011")`，而不是匹配人类语言的消息文本——消息改了测试不挂。

MVP 一共 32 个码，四个前缀对应编译流水线的四个阶段：**LEX（词法）→ PAR（语法）→ SEM/SCH（语义/Schema）→ RUN（执行前置）**。前缀即阶段，用户看码就知道该在哪一层找问题。

## 值得一提的语义区分：SEM-001 vs SEM-012

同样是「找不到字段」，我们有两个码：

- `SEM-001`：字段在**任何历史作用域**都没出现过——多半是拼错；
- `SEM-012`：字段在**之前的阶段可见**（select 裁剪掉了、agg 吞掉了）——这是作用域错误。

实现靠记录流水线每一步的 Schema 快照（`history: Vec<Schema>`），解析失败时查历史。这个区分在教程第 4 章的语义层完成，但**决策属于诊断设计**：报错的精确度决定用户对编译器的信任度。

## hint：把修复建议写进契约

```rust
self.diags.error_hint(
    Code::SemAmbiguousField,
    format!("裸字段 `{}` 存在歧义", name),
    span,
    format!("可指 {}；请用别名限定", candidates.join(" 或 ")),
);
```

效果（真实输出）：

```text
error[SEM-011]: 裸字段 `id` 存在歧义
  ┌─ ambig.pebble:3:11
3 │   .filter(id > 0)
  │           ^^ SEM-011
  提示: 可指 x.id 或 y.id；请用别名限定
```

规范对 hint 有硬性要求（08 §8.4）：作用域错误的 hint 必须列**当前可见**字段，不得列出已被裁剪/隐藏的字段。hint 是帮助，不是噪音——规范层面防止它误导。

## 渲染器：60 行的「穷人版 Ariadne」

Ariadne 是路线图上的项，但渲染逻辑本身很朴素：由 Span 反查行号、列号，重印该行并打 `^`：

```rust
fn locate(source: &str, span: Span) -> (usize, usize, String, String) {
    let mut line_no = 1; let mut line_start = 0;
    for (i, ch) in source.char_indices() {
        if i >= span.start { break; }
        if ch == '\n' { line_no += 1; line_start = i + 1; }
    }
    let col_no = source[line_start..start].chars().count() + 1;
    ...
}
```

先自己实现再换库的好处：换 Ariadne 时你能精确说出**要它解决什么**（多标签子 span、彩色、多行折叠），而不是「因为别人都用」。彩色 ANSI、`--explain`、JSON/SARIF 输出都是这个函数的将来时，契约（`render` 的输入输出）不变。

## RUN 码：编译期与执行期的分界

`RUN-001~004`（非有限输入、Schema 校验失败、终端 IO、资源耗尽）**不由编译器产生**，由 driver 在执行前置检查时产生。规范特别强调（08 §8.3）：RUN 错误不得静默变成字段 null。这条红线把「数据有问题」和「程序有问题」分开——数据问题修数据，程序问题修程序。

## 练习

1. **`--explain`**：加 `pebble --explain SEM-011` 子命令，输出 08-diagnostics 里该码的完整说明（提示：码→文档段落已经是规范里的表，程序化它）。
2. **多标签**：`SCH-002`（join 键类型不匹配）应该同时标注左右两侧。扩展 `Diagnostic` 支持 `Vec<(Span, String)>` 子标签，先在渲染层实现，语义层后面接入。
3. **warning 通道**：MVP 暂不产生 Warning。给 `take` 未紧跟 `sort` 加一条 Warning（提示顺序未定）——想清楚：它为什么不该是 Error？
