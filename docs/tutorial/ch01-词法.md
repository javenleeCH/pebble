# 第 1 章 词法分析：token 模型与错误码

> 对应文件：`crates/pebble-parser/src/lexer.rs`；规范：`docs/draft/spec/02-lexical.md`。

## 本章目标

1. 把源码字符流切成带 `Span` 的 token 流；
2. 学会「**错误码先行**」：词法错误的消息可以改，码（LEX-001~004）是稳定契约；
3. 处理三个经典细节：最长匹配、字符串转义、非法字符的针对性提示。

## 为什么先做词法

编译器前端的每一层都需要回答「错误发生在源码哪里」。词法层是第一个持有位置信息的地方，所以第一个数据结构就是 `Span`：

```rust
// crates/pebble-diagnostic/src/lib.rs
pub struct Span {
    pub start: usize,   // 字符偏移（本实现按 char 计数，渲染层一致即可）
    pub end: usize,
}
```

**实现说明**：教科书用字节偏移，本原型用字符索引做展示层定位，渲染与词法两侧约定一致即可；若未来接入 LSP，切换成字节偏移只需改这两个函数。

## 代码走读

### Token 模型：够用就好

```rust
pub enum Tok {
    Ident(String),
    Int(i128),   // 注意：故意宽于 i64，见下文
    Float(f64),
    Str(String),
    LParen, RParen, LBrace, RBrace, Comma, Dot,
    Eq,     // ==   （比较）
    Assign, // =    （绑定）
    ...,
    AndAnd, OrOr, Not,
    Eof,
}
```

两个设计决策值得停下来讲：

**1. 为什么 `Int` 是 `i128` 而不是 `i64`？**

规范（02-lexical）说「超出 i64 范围在语义层报错」。如果词法层就截断成 i64，`9223372036854775808` 会静默溢出，丢失原始值。所以词法层保真（i128），越界判定推迟到语义层报 `SEM-016`——**错误码归属由规范决定，不由实现方便决定**。

**2. 为什么 `true`/`if` 不是 token？**

它们以 `Ident` 形式存在，由解析器在语法位置识别（上下文关键字）。代价：字段名可以叫 `if` 吗？不能（解析器会当关键字）——这是刻意的取舍：关键字表越小，token 模型越薄，规范与实现的一致性越好检查。`asc`/`desc` 更进一步只做排序位置的上下文识别，所以字段名 `desc` 仍可作普通标识符引用。

## 最长匹配：`>=` 不能拆成 `>` `=`

运算符识别顺序是「先试两个字符，再试单个字符」：

```rust
let two: String = bytes[i..(i + 2).min(n)].iter().collect();
let matched_two = match two.as_str() {
    "==" => Some(Tok::Eq),
    "!=" => Some(Tok::Neq),
    ">=" => Some(Tok::Gte),
    "<=" => Some(Tok::Lte),
    "&&" => Some(Tok::AndAnd),
    "||" => Some(Tok::OrOr),
    _ => None,
};
```

如果不做最长匹配，`>= 18` 会变成 `>` `= 18`——后者是非法序列，报错位置就会错。**词法 bug 的特点是报错位置正确但内容错误**，这类问题只能靠测试矩阵抓（见 `pebble-parser` 的单测）。

## 非法字符：同一个码，不同 hint

`|`（Lambda 已废除）和 `^`（不存在幂运算）都报 `LEX-001`，但 hint 不同：

```rust
let hint = if c == '|' {
    Some("Lambda `|param|` 已废除：使用裸字段或 `别名.字段` 引用".to_string())
} else if c == '^' {
    Some("Pebble 不存在幂运算符 `^`".to_string())
} else {
    None
};
```

这是「**错误码稳定、消息可演进**」的具体实践：迁移期的用户写旧语法 `|u| ...`，得到的是迁移指引而不是裸的「非法字符」。同理 `.5` / `1.` 都进 `LEX-004`，但消息带出具体的原文。

## 字符串：转义与未闭合

四条转义（`\" \\ \n \t`）之外的进 `LEX-003`；行尾没等到引号进 `LEX-002`。注意恢复策略：**LEX-002 时词法层继续扫下一行**，这样一次编译能报出多个词法错误（解析层的多错误恢复是第 8 章的欠账）。

## 跑起来

```powershell
cargo test -p pebble-parser
# 观察 LEX 错误的定位渲染：
"Table(`"a.csv`")`n  .filter(u.a ^ 2 > 1)`n  .collect()" | Set-Content examples/lexdemo.pebble
cargo run -p pebble-driver -- build examples/lexdemo.pebble --locks tests/locks
# 预期 error[LEX-001] + 提示「不存在幂运算符」
Remove-Item examples/lexdemo.pebble
```

## 练习

1. **块注释**：加 `/* ... */` 支持（提示：注意嵌套语义要不要支持、`/*` 未闭合报什么码——建议新增语义还是复用 LEX-002？给出你的理由）。
2. **数字增强**：支持 `1_000` 千分位与 `0x` 前缀吗？先查 02-lexical 规范——规范没写的特性，第一步是改规范和样例，而不是改代码。
3. **词法模糊测试**：写一个测试，把 `>=`, `<=`, `==`, `!=`, `&&`, `||` 的两个字符拆开输入（如 `> =`），确认它们不会被误吞（提示：`>` 后面跟空格时必须只吃一个字符）。
