# 04 表达式

表达式只出现在算子参数中，用于谓词、派生、投影和聚合计算。语言中**没有语句**：除流水线骨架外，一切计算都由表达式描述。MVP 不使用 Lambda；每个表达式直接在其算子定义的解析域中求值。

本章规定语法和静态形式；取值细节见 [07-semantics.md](07-semantics.md)，类型与 Schema 细节见 [05-type-system.md](05-type-system.md)。

## 4.1 运算符优先级

从高到低排列；未特别说明的二元运算符左结合：

| 级别 | 运算符 | 结合性 | 说明 |
|---|---|---|---|
| 1 | `.` 字段访问、`()` 调用、`()` 括号 | 左 | 原子表达式 |
| 2 | 一元 `-`、`!` | 右 | 取负、逻辑非 |
| 3 | `*` `/` `%` | 左 | 乘、除、取模 |
| 4 | `+` `-` | 左 | 加、减；字符串拼接仅 `+` |
| 5 | `==` `!=` `>` `<` `>=` `<=` | 左 | 普通比较或判空测试 |
| 6 | `&&` | 左 | Kleene 逻辑与 |
| 7 | `||` | 左 | Kleene 逻辑或 |

不存在 `^` 运算符。括号可改变优先级。示例：

```pebble
u.age >= 18 && !u.banned
u.first + " " + u.last
(a + b) * c
```

## 4.2 字段引用与解析域

```pebble
u.age
orders.amount
age
```

字段引用先解析为当前解析域中的**稳定字段身份**，再取得其类型；后续阶段不得只按字段名重新解释。

- `别名.字段名`：引用具有该来源身份的可见字段。
- 裸标识符：仅当当前可见 Schema 中该名称唯一时合法；有多个同名字段即报歧义，禁止默认选择左表或最近来源。
- 源别名与输出字段名属于不同命名空间，二者同名不冲突。
- 不存在的字段、不存在的源别名和歧义裸字段均为编译期错误。

各算子的解析域如下：

| 位置 | 可引用内容 |
|---|---|
| `filter` / `extend` / `select` / `sort` | 当前算子的可见输入 Schema |
| `extend` 的每个 RHS | extend 的输入行；同一记录的兄弟绑定不可见 |
| `join on` | 左右两源的字段，以来源别名消歧 |
| `group_by` | 聚合节点的完整输入 Schema |
| `agg` 的聚合参数 | 当前组内的输入行字段 |
| `agg` 的组级部分 | 分组键；同一 agg 的输出绑定互不可见 |
| `having` | 仅分组键与同一 agg 的输出字段（即聚合节点的输出） |
| agg 后的 `filter` / `select` / `sort` | 仅分组键与聚合输出字段，不再包含输入行字段 |
| 全局 agg | 输入行字段只能出现在聚合参数中 |

`select` 之后的可见 Schema 恰好等于 select 输出；被裁字段不得再经源别名访问。无 `as` 的 select 项只能是字段引用；复合表达式必须写成 `expr as name`。无 `as` 的字段引用保留其字段身份；`expr as name` 创建仅以新输出名引用的派生字段。

## 4.3 字面量、null 与严格运算

标量字面量为 `i64`、`f64`、`bool`、`string` 及 `null`。`null` 只能出现在可推导为 `?T` 的位置；无上下文的独立 `null` 报类型无法确定错误。`null == null` / `null != null` 是无类型上下文的判空特例，分别直接得到 bool 常量 true / false。

除以下三类显式例外外，内置标量运算和函数均为严格运算：

1. `x == null` / `x != null` 判空测试；
2. `&&` / `||` 的 Kleene 逻辑；
3. 聚合函数对输入 null 的跳过规则。

严格运算的任一参数为 null，结果即为 null。`if` 是条件选择形式，不因未选分支中的 null 而传播 null。

## 4.4 算术与字符串运算

`+`、`-`、`*`、`/`、`%` 的数值操作数为 `i64` / `f64` 或其可选形式；混合数值运算提升到 `f64`。具体返回类型见 05 章。

- 整数溢出、除零、模零及定义域失败采用 checked-null，不饱和、不抛用户异常。
- `i64 / i64` 向零截断；`i64 % i64` 为与该除法配套的余数，结果符号与被除数一致。
- 有限 f64 运算按 IEEE-754 binary64、round-to-nearest, ties-to-even 求值；结果若将为 NaN 或 ±∞，返回 null。
- `+` 两侧均为 `string` 时执行拼接；字符串与数值不隐式转换。
- 一元 `-` 仅接受数值。

示例：

```pebble
.extend({
  doubled = amount * 2,
  full_name = first + " " + last,
})
```

## 4.5 比较与判空测试

普通比较为 `==`、`!=`、`>`、`<`、`>=`、`<=`：

- 相等比较支持同类型标量；大小比较支持数值与字符串。
- 数值两侧可按算术提升规则比较，不进行字符串与数值之间的隐式转换。
- 普通比较是严格运算，任一操作数为 null 即得到 null；**静态类型一律为 `?bool`**，即使输入 Schema 恰好非空。

`x == null` 与 `x != null` 是独立判空形式，不参与普通比较规则：

- `x == null` 等价于 `is_null(x)`，x 为 null 时返回 `true`，否则返回 `false`。
- `x != null` 等价于 `!is_null(x)`，结果与前者相反。
- 两者恒返回非空 `bool`；对静态非空 x 分别恒为 `false` / `true`。
- `null == null` 为 `true`，`null != null` 为 `false`。

普通 `==` 不用于 group/distinct 的值同一性判断。

## 4.6 逻辑运算

`&&`、`||`、`!` 的操作数必须为 `bool` 或 `?bool`。它们采用强 Kleene 三值逻辑，完整真值表见 07 章。

实现可以短路，但短路不得改变结果。`&&` / `||` 不是普通严格函数：`false && null = false`，`true || null = true`。

## 4.7 if 条件表达式

仅支持值选择型 if，必须有 `else`：

```pebble
level = if s.score >= 90 { "A" }
        else if s.score >= 60 { "B" }
        else { "C" }
```

规则：

1. 条件类型必须为 `bool` 或 `?bool`。
2. 自上而下求值，只选择第一个条件为 `true` 的分支；`false` 和 `null` 都继续测试后续分支。
3. 全部条件均不为 `true` 时选择最终 `else`。
4. 只需求值被选中的分支；未选分支不产生用户可见效果。
5. 分支只能是表达式，不能启动子流水线或修改流水线结构。
6. 分支类型按 05 章的可选类型对齐规则统一；其余类型不隐式转换。

## 4.8 内置函数

MVP 内置函数为白名单制，用户不可定义函数：

| 函数 | 非空参数签名 | 非空参数返回类型 | 说明 |
|---|---|---|---|
| `abs(x)` | `i64` | `?i64` | `abs(i64::MIN)` 为 null |
| `abs(x)` | `f64` | `f64` | 有限输入的绝对值仍为有限值 |
| `round(x)` | `f64` | `f64` | 四舍五入到最近整数，返回 f64 |
| `lower(x)` / `upper(x)` | `string` | `string` | Unicode 16.0 默认全大小写映射，无区域特化 |
| `trim(x)` | `string` | `string` | 去除两端 Unicode 16.0 White_Space 标量值 |
| `length(x)` | `string` | `i64` | 返回 Unicode 标量值数量 |
| `contains(x, y)` | `string, string` | `bool` | 按 Unicode 标量值序列检查字面量子串 |
| `is_null(x)` | 任意标量 | `bool` | 总判空函数 |

上述函数遇 null 参数均严格传播；含可选参数时返回对应可选类型，但 `is_null` 恒返回 `bool`。round 的 halfway 情形采用 round-to-nearest, ties-to-even；其返回值仍遵守 f64 零值规范化规则。

## 4.9 extend 记录字面量

`extend` 唯一接受记录字面量；记录字面量不得出现在其他表达式位置：

```pebble
.extend({
  full_name = u.first + " " + u.last,
  birth_year = 2026 - u.age,
})
```

- 各绑定 RHS **同时对 extend 输入行求值**，兄弟绑定互不可见，书写顺序不影响值。
- 绑定名在一条记录中不得重复。
- 同名字段按 Schema 规则覆盖；覆盖前的旧值不能被后续表达式按原名恢复访问。
- 记录绑定使用 `=`；表达式中没有赋值运算。

## 4.10 聚合表达式边界

MVP 的 agg 绑定右侧必须是直接聚合调用：

```pebble
.agg(
  order_count = count(),
  total_amount = sum(o.amount),
)
```

聚合函数不得出现在 agg 之外，不得嵌套。`count()` 计组内全部行，`count(x)` 计非空 x；`sum/min/max/avg` 跳过 null 参数。完整类型和空输入规则见 05、07 章。

## 4.11 表达式禁止事项

- 禁止 Lambda 形参、函数定义、递归调用及一等函数值。
- 禁止赋值、逗号表达式和语句块。
- 禁止访问当前解析域之外的字段或同一 extend/agg 的兄弟绑定。
- 禁止以顶层 if 选择整条流水线。
- 禁止 NaN、±∞ 字面量；MVP 的 f64 值域只包含有限值。
- 禁止 4.12 节四种转换之外的任何 `cast`。

## 4.12 显式转换 cast（v0.1.1）

受限的显式转换，写法固定为 `cast(expr as T)`。这是语言中**唯一**允许用户书写类型名的位置，且 `T` 只能是 `i64`、`f64`、`string` 三个标量类型之一（不可写 `?T`）。只存在下面四种转换：

| 操作数基础类型 → 目标类型 | 是否可能失败 | 返回类型 |
|---|---|---|
| `i64` → `f64` | 否 | `f64`（操作数可空则为 `?f64`） |
| `f64` → `i64` | 是 | `?i64` |
| `string` → `i64` | 是 | `?i64` |
| `string` → `f64` | 是 | `?f64` |

- 其他任何组合（`bool` 的任何转换、相同类型之间的转换、数值 → `string`）均为编译期错误（SEM-003）。
- cast 是严格运算：操作数为 null 时结果为 null。
- `cast(null as T)` 里的 `null` 没有上下文可用于确定操作数的类型，按 SEM-008 报错。
- 取值规则见 07 章 §7.8；编译期可确定的失败按 SEM-016 诊断。
