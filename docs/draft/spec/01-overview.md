# 01 语言总览

## 1.1 定位

Pebble 是面向**离线批结构化数据**的领域专用语言（DSL）及编译器，专注「结构化数据集的过滤、映射、关联、分组聚合」单一领域。

- **不做通用编程语言**：不提供通用控制流、不开放一等函数。
- **语法即数据流**：阅读顺序 = 数据流动顺序，无嵌套、无临时变量噪音。
- **静态可校验**：Schema 与类型在编译期全部检查，字段错误编译期暴露。
- **可数学化**：所有变换等价于关系代数 / 集合论表达式，可导出 LaTeX 公式。

## 1.2 适用边界

### 适合

- 多表过滤、字段映射、关联查询、分组聚合。
- 指标计算、数据报表生成、实验数据后处理。
- 结构化层面的规则化校验与清洗。
- 可数学化描述的集合变换逻辑。

### 不适合

- 实时无限流处理。
- 业务状态机、控制流程逻辑。
- 通用算法、递归计算。
- 异构数据解析、文本抽取（归属 UniExtract）。
- 任意 IO、网络请求、副作用逻辑。

## 1.3 核心语义模型

### 数据流 DAG

一个 Pebble 程序本质是一张**有向无环图（DAG）**：

- **节点**：算子，代表一次数据变换。
- **边**：数据流向，从上游算子流向下游算子。
- **单入口单出口**：一条流水线只有一个数据源、一个终端输出。

算子执行顺序仅由数据依赖决定；编译器可在不改变结果的前提下自由重排、融合、下推过滤。

### 纯变换与副作用分离

- **变换算子**：`filter`、`map`、`join`、`group_by` 等，纯函数；相同输入必然产生相同输出，无外部影响。
- **终端算子**：`write`、`collect`、`print`，是唯一允许产生副作用的节点。
- **强制规则**：终端算子只能出现在流水线末尾，之后不可再接续任何算子。

### 非图灵完备

从语法与语义两层锁死边界：

1. **语法层**：无 `for` / `while` / `loop` 关键字，无递归函数定义语法。
2. **语义层**：
   - Lambda 仅作为算子的表达式模板，不是一等函数，不可赋值、不可传递、不可返回。
   - 不支持高阶函数、不支持函数自应用。
   - 所有迭代绑定在有限输入集合上，迭代次数 = 集合元素数量，静态可确定。
3. **扩展红线**：新增能力不得引入无界控制流；所有迭代能力必须封装为内置集合原语。

## 1.4 设计红线（不可突破）

1. 不引入通用循环 / 递归语法。
2. 不开放一等函数：Lambda 仅为算子表达式模板。
3. 不放开顶层控制流分支：不允许 `if` 选择整条流水线。
4. 不引入可变全局状态：所有变换无副作用，状态仅存在于算子内部实现。
5. 不支持无限流：所有数据源必须是有限集合，保证程序终止。

## 1.5 程序外观

```pebble
// 单行注释
Table("users.parquet") as u
  .filter(|u| u.age >= 18)
  .map(|u| {
    full_name = u.first + " " + u.last,
    birth_year = 2026 - u.age
  })
  .join(Table("orders.parquet") as o, on: u.id == o.uid)
  .group_by(full_name)
  .agg(
    order_count = count(),
    total_amount = sum(o.amount)
  )
  .sort(total_amount desc)
  .take(100)
  .write("top_users.csv")
```

完整示例见根目录 `examples/`（草稿，样例以根目录为准）。
