# 05 类型系统与 Schema 推导

## 5.1 类型集合

### 标量类型

| 类型 | 字面量 | 值域 / 说明 |
|---|---|---|
| `i64` | `42`, `-10` | 64 位有符号整数 |
| `f64` | `3.14`, `-0.5` | 有限 IEEE-754 binary64；不包含 NaN、±∞ |
| `bool` | `true`, `false` | 非空布尔值 |
| `string` | `"hello"` | 合法 UTF-8 字符串 |

MVP 的 f64 输入约束是语义的一部分：源适配器在表达式求值前验证所有 f64 输入，NaN 或 ±∞ 使输入校验失败，不得由后端静默接受、转换为 null 或自行排序。`-0.0` 与 `0.0` 表示同一 Pebble 数值，所有产生零的 f64 运算规范化为 `+0.0`。

### 可选类型

`?T` 表示值可能为 `null`，如 `?string`、`?i64`。`??T` 不是合法类型；对 `?T` 再加可选标记仍为 `?T`。

- `null` 只能出现在可选类型位置。
- 严格运算遇 null 返回 null；判空、Kleene 逻辑和聚合跳过规则是显式例外。
- `x == null` / `x != null` 对任意标量 x 均合法并恒返回 `bool`；对非空 x 可分别静态化简为 false / true。
- 可空性只由类型表达，不存在平行的 `FieldSchema.nullable` 标志。

### 行类型与字段身份

一行是**有序字段序列**。每个字段至少包含：

```text
Field = { field_id, output_name, type, origin? }
```

- `field_id` 是编译期稳定身份，用于名称解析和流敏分析。
- `output_name` 是裸字段名称及最终输出名称。
- `origin` 是可选的来源别名；派生字段可以没有 origin。
- 中间 Schema 允许相同 output_name，裸引用此时歧义；限定引用按 origin 与字段身份消歧。
- 进入要求唯一列名的输出边界前必须消除重名，禁止实现自动改名。

## 5.2 表达式类型推导

### 基础提升与可选性

数值算术先将操作数去除可选标记，再按下表确定基础类型：

| 操作数基础类型 | 基础结果类型 |
|---|---|
| `i64` 与 `i64` | `i64` |
| `i64` 与 `f64`（任意侧） | `f64` |
| `f64` 与 `f64` | `f64` |

i64 转 f64 使用 IEEE-754 round-to-nearest, ties-to-even。字符串与数值之间无隐式转换。

### 运算返回类型

| 表达式形式 | 返回类型 | 原因 |
|---|---|---|
| `i64 + - * / % i64` | `?i64` | 整数运算可能溢出或除/模零 |
| 一元 `-: i64` | `?i64` | `-i64::MIN` 不可表示 |
| 含 f64 的 `+ - * / %` | `?f64` | 除/模零或结果可能成为非有限值 |
| 一元 `-: f64` | `f64` | 有限值取负仍有限，零规范化为 +0 |
| `string + string` | `string` | 拼接 |
| 普通 `== != > < >= <=` | `?bool` | 普通比较采用严格 null 语义 |
| `x == null` / `x != null` / `is_null(x)` | `bool` | 总判空测试 |
| `!x` | 与 x 的可空性一致的 bool/?bool | Kleene 非 |
| `x && y` / `x || y` | 任一参数可空则为 `?bool`，否则 `bool` | 保守而统一的 Kleene 类型 |
| 严格函数 | 按非空签名得到基础结果；任一参数可空则结果可选 | `is_null` 除外 |
| `cast(x as f64)`，x 基础类型为 `i64` | `f64`；x 可空则为 `?f64` | 转换永不失败（04 §4.12） |
| `cast(x as i64)`，x 基础类型为 `f64` | `?i64` | 取整结果可能越界 |
| `cast(x as i64)` / `cast(x as f64)`，x 基础类型为 `string` | `?i64` / `?f64` | 解析可能失败 |

严格字符串拼接中任一参数可空时结果为 `?string`。可能失败的运算即使参数非空也保持表中的可选返回类型，禁止声明为 `i64`/`f64` 后在运行时临时产生 null。

普通比较的静态类型一律为 `?bool`；该规则有意不依赖操作数的当前可空性，以避免普通相等与判空测试因 Schema 细化而改变语法类别。

### if 分支类型统一

设两个分支类型为 A、B：

1. A 与 B 完全相同，结果为 A。
2. 一个为 `T`，另一个为 `?T`，结果为 `?T`。
3. 其他情况报类型不一致；数值分支之间不隐式提升。

`null` 分支通过另一分支推导为对应的 `?T`。两个分支都仅为无上下文 `null` 时无法确定 T，报编译错误。

### 内置函数

非空参数签名及定义域失败见 04 章。严格函数在参数可空时返回可选类型；`abs(i64)` 本身即返回 `?i64`，`abs(?i64)` 仍为 `?i64`。

## 5.3 Schema 自动推导

### 源算子

- `Table(path)` / `MemoryTable(name)`：仅从锁定或宿主注册的不可变 Schema 元信息推导输入 Schema。
- 源别名在同一流水线中必须唯一；它与字段名处于不同命名空间。
- 数据源缺少 Schema、Schema lock 不匹配或 f64 输入含非有限值均不得进入正常表达式求值。

### 变换算子

| 算子 | 输出 Schema 规则 |
|---|---|
| `filter(pred)` | 保留字段及顺序；将谓词的非空保证集合中的 `?T` 字段收缩为 `T` |
| `having(pred)` | 与 `filter` 相同（它就是作用于聚合输出的 filter） |
| `extend(record)` | 保留未覆盖字段；覆盖字段留在原位置并替换字段身份、类型与值；新字段按绑定顺序追加 |
| `select(...)` | 仅保留显式项，顺序与列出顺序一致；输出名不得重复 |
| `distinct()` | 与输入 Schema 一致 |
| `sort(...)` | 与输入 Schema 一致 |
| `take(n)` | 与输入 Schema 一致 |
| `join(other, on = cond)` | 左字段序列后接右字段序列，保留各自 field_id/origin；同名字段不合并、不自动改名 |

extend 覆盖后，旧字段身份及其值不再可访问；覆盖字段是没有 origin 的新派生字段，后续以输出名引用，旧源限定名不得重新指向它。所有 RHS 只看到覆盖前的同一输入 Schema。

select 的无 `as` 字段项保留字段身份和 origin；`expr as name` 生成没有来源限定的新派生字段。select 后不可再访问未保留字段。

### filter 的非空保证分析

对谓词 p 计算 `NN(p)`：若 p 在当前行上求值为 `true`，则该集合中的字段必然非空。分析基于规范字段身份，先消除冗余括号，最小规则如下：

1. `NN(f != null) = NN(!(f == null)) = NN(!is_null(f)) = {f}`。
2. `NN(a && b) = NN(a) ∪ NN(b)`。
3. `NN(a || b) = NN(a) ∩ NN(b)`。
4. 对 `if c { a } else { b }`，分别分析“c=true 且 a=true”和“c 不为 true 且 b=true”两条路径，结果取两条路径保证的交集。
5. c=true 路径继承 `NN(c)`；c 不为 true 路径仅在 c 是总判空形式 `f == null` 或 `is_null(f)` 且其值确定为 false 时继承 `{f}`。其他否定条件不猜测非空事实。
6. 其他原子谓词的 `NN` 为空集。

嵌套 if 按同一规则递归。分析**可靠但不完备**：例如 `filter(f > 0)` 虽在运行时只有非空 f 才能通过，MVP 仍不据此收缩。无法证明时保持 `?T`。

收缩只修改当前 filter 输出 Schema，不做运行时转换，不跨 extend/select/join/agg 自动逆向传播。未来 having 可复用该算法。

### 聚合算子与作用域

`group_by + agg` 是单个聚合节点，其输入始终是完整分组关系，不存在“group_by 先丢弃非键列”的中间 Schema。

- 分组键按列出顺序成为输出前缀；`group_by(u.first)` 默认输出名 `first`。
- 去限定后重名的分组键在 MVP 中直接拒绝，禁止自动改名。
- 聚合绑定按书写顺序追加；绑定名不得与分组键或其他聚合输出重名。
- 全局 agg 没有分组键，输出恰好为聚合绑定序列。
- 同一 agg 的输出绑定互不可见；agg 后仅输出字段可见。

### 聚合返回类型

以下“非空参数”指参数静态类型为 `T` 而非 `?T`。T 为去除可选标记后的标量类型。

| 聚合 | 上下文与参数 | 返回类型 |
|---|---|---|
| `count()` / `count(x)` | 任意上下文 | `i64` |
| `min(x)` / `max(x)` | 分组聚合且 x 非空 | `T` |
| `min(x)` / `max(x)` | 全局聚合，或 x 可空 | `?T` |
| `avg(x)` | 分组聚合且 x 非空 | `f64` |
| `avg(x)` | 全局聚合，或 x 可空 | `?f64` |
| `sum(x)` | 任意上下文 | `?T`，其中 T 只能为 i64/f64 |

整数 sum 即使对分组内的非空参数也返回 `?i64`，因为精确总和可能溢出。f64 sum 也始终可空，因为空集合为 null，且有限加数的精确总和可能超出有限 f64 值域。avg 对非空分组参数不可能无值，其数学平均值位于有限输入的最小值与最大值之间，故返回非空 `f64`。

`min/max` 接受 `i64`、`f64`、`string` 及其可选形式；`sum/avg` 只接受数值及其可选形式。所有可空聚合结果仍是普通 `?T` 值，可直接比较、参与严格运算和 sort，不存在隐式或异常式解包。

## 5.4 静态校验

编译期完成全部检查，错误定位到源码位置：

| 检查项 | 报错条件 |
|---|---|
| 字段存在性 | 引用了当前解析域中不存在的字段 |
| 字段歧义 | 裸字段对应当前 Schema 中多个字段身份 |
| 来源与作用域 | 来源别名不存在、select 后访问裁剪字段、agg 后访问输入行字段 |
| 类型匹配 | 运算符 / 函数 / 聚合参数类型不兼容 |
| 谓词类型 | filter、join on、if 条件不是 bool/?bool |
| 分支类型 | if 分支不能按可选规则统一 |
| 可选类型 | null 用于非可选位置或无法确定 null 的基础类型 |
| 常量定义域 | 编译期可确定的除零、模零、溢出或非有限 f64 结果 |
| 绑定可见性 | extend/agg RHS 引用同一记录的兄弟绑定 |
| 名称唯一性 | 源别名、单条记录绑定、select 输出、分组键或聚合输出发生禁止的重复 |
| 算子位置 | agg 位置非法、聚合函数嵌套或出现在 agg 之外、`having` 未紧跟 `agg` |
| 显式转换 | `cast` 的操作数类型与目标类型不是 04 §4.12 列出的四种组合（含相同类型、`bool`、数值 → `string`） |
| join 输入 | join 右表不是当前语法允许的源算子 |
| 输出 Schema | 到唯一列名边界仍存在重名 |

静态非空收缩只改变类型，不插入判空分支，也不改变谓词求值结果。

## 5.5 类型标注与后端边界

- MVP 不支持用户手写类型标注、自定义类型或泛型；唯一的例外是 `cast(expr as T)` 的目标类型，且 `T` 只能是 `i64` / `f64` / `string`（04 §4.12）。
- 类型信息由源 Schema 与表达式推导；无法确定时必须报错，不做运行时猜测。
- 本章规则是后端无关的语言契约。DuckDB MVP、后续 Polars 以及未来原生后端都必须实现同一类型和可空性结果；后端自身的 null、整数溢出或浮点行为不得反向修改语言规范。
