# 07 语义规则

本章是后端无关的语言值语义。任何优化、代码生成或并行执行都必须保持本章规定的可观察结果；后端自身的 SQL、表达式或浮点习惯不是语言规范。

## 7.1 数据流与多重集语义

- 程序是一张算子节点 + 数据依赖边的 DAG；MVP 语法为单条线性流水线，内部 HIR 仍按 DAG 组织。
- 除 sort/take 的表示层顺序外，关系是有限**多重集**，行数与重复行均有意义。
- 每个算子读取上游关系，产出新关系；算子之间不共享可变状态。
- `extend` 是扩展算子 ε，`select` 是投影 π，`filter` 是选择 σ。
- `group_by + agg` 是单个聚合节点，输入是完整分组关系，输出为分组键与聚合字段。
- `sort/take` 是代数外的表示层算子和顺序哨兵。自由重排只适用于无顺序依赖的代数片段，不得跨越哨兵。

编译器可以下推 filter、合并投影或并行执行，但必须同时保持值、Schema、可空性及规定的顺序行为。filter 的非空收缩是静态类型保证，不得被优化器当成额外运行时分支。

## 7.2 纯变换、确定性与效应边界

- 变换与聚合满足引用透明：相同输入产生相同输出，不读取外部状态，不产生外部影响。
- 结果不依赖系统时间、随机数、环境变量或哈希表迭代顺序。
- 算子内部可使用排序缓冲区、哈希表等临时状态，但不得暴露到语言层。
- 只有显式终端能力具有受控副作用：`write` 写文件，`collect` 回传宿主，`print` 写标准输出。
- 终端只能位于流水线末尾，其后不得接续算子。

## 7.3 有限性、终止性与执行失败

- 所有数据源有限；语言无 for/while/loop、用户递归、无界迭代或无限流。
- 终止性不表示有界时间/内存，也不替代宿主取消、OOM 或资源配额机制。
- 用户表达式的定义域失败采用 checked-null，不产生用户可见异常。
- 输入校验失败、IO、OOM、取消、配额耗尽是**执行状态**，不得静默转换为字段 null。

## 7.4 表达式解析域与无 Lambda 规则

语言没有 Lambda 形参或一等函数。表达式直接按当前算子的解析域绑定字段：

- 裸字段只有名称唯一时才能解析；多源重名必须别名限定。
- 源别名与输出字段名属于不同命名空间。
- extend 的所有 RHS 对同一输入行同时求值，兄弟绑定互不可见。
- select 后仅其输出字段可见；被裁字段不能经源别名复活。
- agg 参数引用组内输入行，分组键是组级值，同一 agg 的输出绑定互不可见。
- agg 后只能引用分组键与聚合输出，不再存在唯一输入行。
- 全局 agg 中，输入行字段只能出现在聚合参数内。

详细 Schema 转换与类型推导见 05 章。

## 7.5 null、严格运算与判空

`null` 表示值缺失，仅存在于 `?T`。除判空测试、Kleene 逻辑及聚合输入跳过规则外，内置标量运算和函数均为严格运算：任一参数为 null，结果为 null。

判空测试是总运算：

| 表达式 | x=null | x 非 null | 静态类型 |
|---|---:|---:|---|
| `x == null` / `is_null(x)` | true | false | `bool` |
| `x != null` / `!is_null(x)` | false | true | `bool` |

`null == null` 为 true，`null != null` 为 false。判空形式不得按普通相等比较解释。

## 7.6 普通比较与 Kleene 三值逻辑

普通 `==`、`!=`、`>`、`<`、`>=`、`<=` 是严格比较，任一输入为 null 即返回 null，静态类型为 `?bool`。非空数值按数值序比较，非空字符串按 Unicode 标量值序列的字典序比较。

逻辑值域为 `{true, false, null}`。真值表如下，其中 U 表示 null：

逻辑非：

| x | !x |
|---|---|
| true | false |
| false | true |
| U | U |

逻辑与：

| a && b | b=true | b=false | b=U |
|---|---|---|---|
| **a=true** | true | false | U |
| **a=false** | false | false | false |
| **a=U** | U | false | U |

逻辑或：

| a || b | b=true | b=false | b=U |
|---|---|---|---|
| **a=true** | true | true | true |
| **a=false** | true | false | U |
| **a=U** | true | U | U |

实现可以短路，但结果必须等于上述真值表。逻辑连接词是普通严格传播的显式例外。

## 7.7 谓词与 if

filter、having、join `on` 及 if 条件均接受 `bool/?bool`。**成立当且仅当值为 true**；false 和 null 均不成立。

- filter 只保留 pred=true 的行。
- join 只保留 on=true 的行对，因此普通等值 join 不匹配 null 键。
- if 自上而下选择第一个条件为 true 的分支；false/null 继续后续分支，全部不成立时取 else。
- if 只求值被选分支，不传播未选分支的 null。

filter/having 的非空保证使用 05 章的 NN 分析。该分析可靠但不完备，不能从析取单侧或未经证明的表达式等价关系收缩字段。

## 7.8 checked-null 与数值语义

### 整数

所有 i64 算术先按数学整数求精确结果，再检查结果定义域：

- 精确结果超出 `[-2^63, 2^63-1]` 时返回 null，不饱和、不回绕。
- `/0`、`%0` 返回 null。
- 非零整数除法向零截断；余数满足 `a = (a / b) * b + a % b`，其符号与被除数一致。
- `i64::MIN / -1`、`i64::MIN % -1` 的数学商不可表示：前者返回 null；后者的数学余数为 0，但为避免后端对陷阱指令的依赖，统一规定该组合整体返回 null。
- 一元 `-i64::MIN` 与 `abs(i64::MIN)` 返回 null。

编译期可确定的非法常量直接诊断；动态输入上的同类失败返回 null。返回类型的可空性按 05 章静态推导。

### f64 值域与运算

MVP 仅允许有限 IEEE-754 binary64 值。NaN、±∞ 不得作为字面量、输入值或正常中间值：

1. 源适配器在表达式求值前验证输入；发现非有限值即输入校验失败。
2. 有限操作数按 IEEE-754 binary64、round-to-nearest, ties-to-even 执行单个算术运算；若结果将为 NaN 或 ±∞，返回 null。
3. f64 除零、模零返回 null；f64 `%` 是与向零截断商配套的余数，非零有限操作数的结果为有限值。
4. `-0.0` 与 `+0.0` 数值相等；任何产生零的 f64 运算、函数或聚合均规范化为 `+0.0`。
5. 普通比较采用有限实数序，因此不存在 NaN 比较分支。

以上规则不允许后端用自身默认的 Infinity/NaN 结果替代 checked-null。

### 显式转换 cast

四种转换的取值都与后端无关：

- `i64 → f64`：按 IEEE-754 round-to-nearest, ties-to-even 得到最接近的 f64（可能丢失精度，但永不失败）。
- `f64 → i64`：先把 x 按 round-to-nearest, ties-to-even 取整为整数 r；r 落在 `[-2^63, 2^63-1]` 内则结果为 r，否则 null。例如 `cast(2.5 as i64) = 2`、`cast(-2.5 as i64) = -2`、`cast(1e300 as i64) = null`。
- `string → i64`：字符串必须匹配 `[+-]?[0-9]+`（ASCII；不允许空白、小数点、下划线、进制前缀），且数值在 i64 值域内；否则 null。`"-0"` 得到 0。
- `string → f64`：字符串必须匹配 `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?`（ASCII 十进制或科学记数法），取最接近的 f64（round-to-nearest, ties-to-even）。结果非有限（如 `"1e400"`）则为 null；下溢得到 0 并遵守零值规范化。`"inf"`、`"nan"` 等写法不合法。

后端不得直接沿用引擎自己的字符串解析或取整习惯：引擎若接受更宽的写法（空白、下划线、`inf`）或采用别的取整方向，后端必须用守卫把它们收敛到本节的规则。
## 7.9 聚合语义

### 输入、空组与 null

- `count()` 返回组内全部行数，包括所有字段均为 null 的行。
- `count(x)` 只计 x 非 null 的行。
- `sum/min/max/avg` 先跳过参数为 null 的行，再对其余值聚合。
- 分组聚合只由实际输入行形成组；空输入产生零组、零行，不人为创造空分组。
- 全局 agg 对任意输入恰好产生一行；空输入形成一个空全局组。
- 空全局组中 count() 和 count(x) 均为 0。
- sum 没有非空输入时为 null；min/max/avg 没有非空输入时均为 null。
- avg 的结果为 `?f64` 时以 null 表示无值；非空分组上的非空参数 avg 返回 `f64`。

### 精度与确定性

- i64 sum 以数学整数精确求和，超出 i64 值域时返回 null。
- f64 sum 以有限输入的数学实数总和为语义值，再一次性按 round-to-nearest, ties-to-even 转换为 f64；超出有限值域则返回 null。不得让并行求和顺序影响语言语义。
- avg 以非空输入的数学实数平均值为语义值，再一次性转换为 f64；有限输入的平均值必为有限值。
- min/max 使用本章的普通非空值序；多个零值的最小/最大结果均为规范化 `+0.0`。

聚合返回类型完整矩阵见 05 章，可空结果可直接比较、运算或 sort，不进行隐式/异常式解包。

## 7.10 值同一性、分组与 distinct

group_by 和 distinct 使用独立的**值同一性**，不得复用普通 `==`：

| 类型 | 同一性规则 |
|---|---|
| 可选类型 | 两个 null 彼此同一；null 与非空值不同一 |
| i64 / bool | 值相同即同一 |
| f64 | 有限实数值相同即同一；±0 同一；非有限值不合法 |
| string | Unicode 标量值序列完全相同即同一 |

复合行/分组键逐字段同一。group_by 将所有键同一的行放在同一组，包括键字段为 null 的行；distinct 将整行同一的重复行折叠为一行。该规则与普通等值 join 对 null 的处理不同，是有意的算子语义差异。

## 7.11 顺序、sort 与 take

- 未显式 sort 时，行顺序不属于关系语义，优化器可重排。
- sort 按给定键从左到右做字典序排序。
- 所有键统一 `nulls last`，不随 asc/desc 反转；asc/desc 只反转非空值顺序。
- 非空数值使用数值序，字符串使用 Unicode 标量值序列字典序，bool 使用 false < true。
- ±0 排序键相等；MVP 不存在 NaN/±∞ 的排序分支。
- 并列键不承诺稳定顺序；需要确定性 take 边界时，用户必须提供足以区分所需行的排序键。
- take(n) 保留前 n 行；未排序输入上的 take 不保证选中哪些并列或无序行。

## 7.12 设计红线与后端一致性

| 红线 | 语义层强制手段 |
|---|---|
| 无通用循环/递归 | 文法无对应产生式，无函数定义与递归路径 |
| 无一等函数 | 无 Lambda 和函数值类型，聚合仅调用白名单内置函数 |
| 无顶层控制流 | if 只能出现在表达式位置，流水线结构不可由条件选择 |
| 无可变全局状态 | 算子接口按纯函数设计，外部效应仅经显式能力边界 |
| 无无限流 | 源只接受有限关系，无拉取/订阅语法 |
| 语义封闭 | null、数值、聚合、排序和作用域均按本章执行，无实现定义分支 |

DuckDB 是 MVP 首个产品后端；Polars 是后续适配后端，Cranelift/MLIR 仅属于未来原生后端路线。后端先后次序不改变本章契约，所有后端必须通过同一组边界与差分语义测试。
